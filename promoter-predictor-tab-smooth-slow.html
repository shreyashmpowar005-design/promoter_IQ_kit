Learn: how strength is actually measured in the lab

Your model predicts strength computationally — but real labs measure it experimentally, using a GFP reporter assay. Walk through the real 4-step process below and see how it connects to the number your model outputs.

1
2
3
4

Step 1 — Clone: the candidate promoter is inserted upstream of a GFP reporter gene on a plasmid, then transformed into E. coli cells. This is the wet-lab equivalent of typing a sequence into the Predict tab.

Step 2 — Grow: transformed cells are grown in liquid culture for several hours. As the population grows (tracked via OD600, a measure of cell density), each cell is also actively expressing GFP at a rate set by the promoter's strength.

Step 3 — Measure: a plate reader (fluorometer) shines light on each well and measures how much green fluorescence comes back — brighter glow means more GFP was made, meaning the promoter drove more expression.

Strength  =  FluorescenceOD600  ÷  reference promoter value
–
Educational simulation only: these values are illustrative and are not measured laboratory results or a verified reconstruction of the Anderson dataset.

Step 4 — Calculate: raw fluorescence is divided by OD600 (to normalize for how many cells were actually measured), then divided by a reference promoter's value — giving a clean relative strength number, just like the one your model predicts.

About

🧬

The Synthetic Promoter Strength Predictor is an educational bioinformatics mini project. It encodes DNA using overlapping 3-mer counts and fits a ridge-regularized linear regression model to labels generated by a synthetic rule. It includes sequence analysis, batch/FASTA tools, candidate comparison, an educational lab simulation, and local prediction history. The default synthetic model has not been validated against a verified experimental dataset; its scores are demonstrations only. A separate CSV workspace supports preliminary evaluation of user-supplied measured data, but does not establish laboratory readiness.

Project methodology and limitations

Problem statement: demonstrate how a DNA sequence can be transformed into numerical features and analyzed with a simple regression model in a browser.

Objective: provide an interactive learning tool for DNA composition, overlapping K-mers, model training, and candidate comparison—not a clinical or laboratory decision system.

Workflow: validate DNA input → extract overlapping 3-mer counts (64 possible features) → standardize features using training-set statistics → fit ridge-regularized linear regression → display a synthetic-demo score.

Training labels: generated in the browser from a simple synthetic rule involving GC content, an inserted TATAAT-like pattern in some sequences, and random noise. Therefore, metrics describe recovery of that artificial rule only.

Technologies: HTML, CSS, vanilla JavaScript, browser Canvas/SVG, and browser-local storage. The current project does not call a remote model or use a backend.

Limitations: no verified independent experimental dataset is loaded; no real biological predictive performance is established; motif associations are not causal evidence; and browser-local login is only a classroom demonstration, not secure account authentication.

Future scope: load a traceable experimental dataset with documented assay conditions, evaluate on an independent split, compare against a baseline, report MAE/RMSE/R² (or suitable classification metrics), and use a secure backend if real accounts are required.

Dataset reference to verify before use: iGEM Registry — Anderson Promoter Catalog. This link is a starting point for sourcing data, not evidence that the current model has been validated against it.
